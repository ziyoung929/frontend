# 겹 — 6명의 동료가 1시간 회의를 잡는 경험

> "여러 사람의 조건을 한 번에 이해하고, 모두에게 괜찮은 시간을 찾는" 회의 일정 조율 프로토타입

**데모 실행**: `index.html`을 브라우저에서 열면 바로 동작합니다. (빌드·의존성 없음, 단일 HTML 파일)

## 시나리오

같은 회사 동료 6명이 다음 주(7/13–7/17)까지 1시간 회의를 잡아야 합니다.

- **박준호**는 점심 직후(13–14시)를 피하고 싶어하고
- **이수민**은 화·목요일에 종일 외근이며
- **김지영·박준호·이수민·최다은**은 꼭 참석해야 하고, **정우성·한소라**는 선택 참석입니다.

---

## 1. 어떤 문제를 발견했나요? 왜 문제라고 생각했나요?

여러 명의 일정 조율이 어려운 진짜 이유는 "빈 시간이 없어서"가 아니라, **사람들의 가용성이 가능/불가 두 가지가 아니기 때문**이라고 봤습니다.

1. **선호가 담길 곳이 없다.** "점심 직후는 피하고 싶다"는 불가가 아니라 선호입니다. 기존 도구(When2meet, 캘린더 겹쳐보기)는 이진값만 받기 때문에 이런 맥락은 채팅과 구두로 흩어지고, 주최자는 그것을 머릿속에서 조합해야 합니다. 6명이면 조건 조합은 사람의 작업 기억을 넘어섭니다.
2. **참석자의 무게가 모두 같게 취급된다.** 필수/선택을 구분하지 못하면 선택 참석자 한 명의 일정 때문에 "모두 되는 시간이 없네요"가 되어 회의 전체가 미뤄집니다.
3. **자동 추천은 판단 근거를 숨긴다.** "이 시간이 최적입니다"라고 정답 하나만 내밀면 주최자는 "왜?"를 확인할 수 없어 결국 다시 수동으로 검증합니다. 과제가 요구하는 것도 "동료들의 상황을 **이해하고**" 잡는 경험입니다.

## 2. 그 문제를 어떻게 해결했나요?

**응답을 3단계로, 참석자에 가중치를, 판단 근거를 화면에.**

- **3단계 응답** — 참석자는 `가능 / 피하고 싶음 / 불가`로 답합니다. "되긴 하지만 피하고 싶은 시간"이 일급 데이터가 되어 주최자에게 그대로 전달됩니다. (참석자 응답 화면에서 칠하듯 입력)
- **필수/선택 가중치** — 필수 참석자의 '불가'만 시간을 막습니다. 필수의 '피하고 싶음'과 선택 참석자의 사정은 점수만 낮춥니다. 배지를 눌러 필수↔선택을 바꾸면 추천이 즉시 재계산됩니다.
- **가용성 히트맵** — 칸 하나 = 그 시각에 시작하는 1시간 회의. 진할수록 모두에게 편한 시간, 빗금은 필수 참석자가 안 되는 시간. "화·목은 수민님 외근으로 통째로 불가" 같은 구조가 한눈에 보입니다.
- **이유가 달린 추천 3개** — "6명 전원 가능" / "필수 4명 모두 가능 · 준호님은 피하고 싶은 시간"처럼 사람이 읽는 문장으로 근거를 설명합니다.
- **칸 상세 → 확정** — 아무 칸이나 누르면 6명 각각의 상태와 이유(회의명, 외근, 선호)가 보이고, 그 자리에서 확정하면 전원에게 초대가 갑니다. 피하고 싶은 시간에 확정된 사람에게는 양해 메시지를, 불참하는 선택 참석자에게는 회의 노트 공유를 안내합니다.

## 3. 왜 이 방식으로 설계했나요?

- **계산은 도구가, 판단은 사람이.** 최적 시간을 찾는 조합 계산은 도구가 잘하는 일이지만, "준호가 피하고 싶어해도 이번엔 어쩔 수 없다"는 판단은 팀의 맥락을 아는 사람의 몫입니다. 그래서 정답 하나를 내미는 대신 지형 전체(히트맵)와 근거(상세 패널)를 보여주고, 추천은 출발점으로만 제공했습니다. 근거가 보여야 결정을 신뢰하고, 동료의 사정을 이해한 채로 결정해야 확정 후의 마찰(불만, 재조정)이 줄어듭니다.
- **선호는 절대 시간을 막지 않는다.** 현실에서 "피하고 싶다"는 협상 가능한 조건입니다. 선호를 불가와 똑같이 취급하면 잡을 수 있는 회의도 못 잡게 되고, 사람들은 학습을 통해 선호를 아예 입력하지 않게 됩니다. 색의 진하기로만 반영해 정보는 살리고 결정은 막지 않았습니다.
- **참석자의 입력 비용을 최소로.** 조율 도구는 응답률이 생명이라, 참석자 화면은 모드 고르고 칠하는 것이 전부입니다. 대신 그 얇은 입력이 주최자 화면에서 풍부한 맥락(누가 왜 어려운지)으로 번역됩니다.
- **확정 이후까지가 경험이다.** 시간을 고르는 것으로 끝나지 않고, 피하고 싶던 시간에 잡힌 동료에게 양해를, 불참자에게 노트 공유를 자동으로 안내해 "잡고 나서의 어색함"까지 설계에 포함했습니다.

## 화면 구성

| 화면 | 내용 |
|---|---|
| 주최자 화면 | 참석자 6명(필수/선택 토글, 사정 요약) · 추천 시간 3개 · 주간 히트맵 · 칸 상세 패널 · 확정 플로우 |
| 참석자 응답 화면 | 박준호 시점. 가능/피하고 싶음/불가 3모드로 30분 단위 칠하기, 저장 시 주최자 화면에 즉시 반영 |

## 기술 노트

- 의존성 없는 단일 HTML (vanilla JS + CSS custom properties)
- 라이트/다크 테마 지원 (`prefers-color-scheme` + `data-theme` 오버라이드)
- 키보드 접근 가능 (모든 칸이 button, Esc로 패널 닫기), `prefers-reduced-motion` 존중
- 점수 모델: 필수 불가 = 차단, 필수 '피하고 싶음' −22, 선택 불가 −15, 선택 '피하고 싶음' −7 (100점 만점, 히트맵 농도와 추천 순위에 사용)
